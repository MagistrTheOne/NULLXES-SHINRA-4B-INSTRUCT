# SHINRA S1 Language + Semantics Data Specification

Status: DESIGN FREEZE
Parent: S0.4.1
Contract: S1_CONTRACT.md
Stage: S1 Language + Semantics
Revision: S1.0

## 1. Objective

Build a compact but semantically diverse supervised curriculum that improves
general language understanding and semantic routing before larger-scale
post-training.

S1.0 is an acquisition experiment.

It is not intended to exhaust the full language curriculum.

Primary question:

Does broader semantic supervision improve unseen semantic generalization,
including the unresolved Stage 0 routing failures, without directly training
on the frozen Stage 0 blind probes?

## 2. Initial Scale

Target TRAIN size:

approximately 12,000,000 supervised target tokens

Allowed construction range:

10,000,000 to 14,000,000 supervised target tokens

The final manifest must record the exact count before training.

DEV and BLIND are not counted toward the TRAIN token budget.

Do not silently increase the training budget after seeing DEV or BLIND results.

## 3. Language Mixture

TRAIN target:

English: 50%
Russian: 50%

Tolerance after tokenization:

English: 47% to 53%
Russian: 47% to 53%

This balance is deliberate for S1.0 diagnostics.

Russian data must not consist primarily of translations from English.

English data must not consist primarily of translations from Russian.

Each language requires independently authored examples and independently
sampled source material.

## 4. Capability Mixture

Target mixture by supervised target tokens:

instruction_semantics     15%
relation_semantics        15%
polarity_negation         12%
paraphrase_equivalence    12%
reference_coreference     10%
entailment_contradiction  12%
extraction_transform      10%
short_qa                   5%
controlled_generation      4%
identity_replay            5%

TOTAL                     100%

Tolerance for non-identity families:
plus or minus 2 percentage points.

Identity replay:
target 5%
hard maximum 6%

Identity replay must never become a dominant correction mechanism.

## 5. Semantic Difficulty

TRAIN should contain a controlled mixture of:

Level A:
direct lexical formulations

Level B:
syntactic variation

Level C:
lexical paraphrases

Level D:
relation reversals and hard negatives

Level E:
short contextual examples requiring local reference resolution

Approximate target distribution:

A 15%
B 20%
C 30%
D 25%
E 10%

The curriculum must not consist primarily of template substitutions.

## 6. Example Structure

Every normalized S1 record must contain at least:

- id
- lang
- family
- difficulty
- source_type
- prompt
- expected
- split

Optional fields:

- context
- source_dataset
- source_record_id
- license
- generation_method
- semantic_signature
- template_family
- negative_type
- metadata

Normalized records must be serializable as JSON.

## 7. Source Types

S1 may combine:

PUBLIC:
external public datasets whose license and provenance have been reviewed.

NATIVE:
NULLXES-authored curriculum examples.

SYNTHETIC:
generated examples that pass deterministic and/or manual validation.

DERIVED:
transformations of legally usable source material where provenance remains
traceable.

Every record must retain source_type.

External provenance must not be discarded during normalization.

## 8. Source Mixture Principle

No single external dataset should define the semantics of S1.

Target design:

public / derived material:
50% to 70%

NULLXES native curriculum:
20% to 35%

validated synthetic material:
10% to 25%

These ranges describe TRAIN composition and may overlap only through an
explicitly documented classification rule.

The final dataset manifest must report the exact realized mixture.

## 9. Hard Negatives

Hard negatives are required for:

- relation_semantics
- polarity_negation
- entailment_contradiction
- identity_replay where applicable

Examples include:

- subject/object reversal
- creator/entity reversal
- positive/negative proposition reversal
- supported/contradicted proposition pairs
- identity/creator distinction
- same lexical vocabulary with different semantic relation

Hard negatives must alter meaning, not merely punctuation or surface form.

## 10. Identity Replay

Identity replay target:
5% of supervised TRAIN target tokens.

It may teach only the frozen Stage 0 identity boundary:

NAME = SHINRA
CREATOR = NULLXES
SHINRA != NULLXES

Identity replay may include new training paraphrases.

It must NOT contain exact S0.5 or S0.7 blind prompts.

It must NOT be generated by mechanically mutating blind prompts.

It must NOT introduce biography, mission, personality, consciousness,
gender identity, or product-category claims.

The objective is retention plus semantic transfer, not benchmark fitting.

## 11. Split Policy

TRAIN:
gradient updates allowed.

DEV:
checkpoint selection allowed.
gradient updates forbidden.

BLIND:
checkpoint selection forbidden.
gradient updates forbidden.
inspection of aggregate results only after the gate is frozen.

S0 REGRESSION:
existing Stage 0 frozen evaluation assets.
training forbidden.
checkpoint selection forbidden.

No exact prompt overlap is allowed between TRAIN, DEV, and BLIND.

## 12. Leakage Controls

Before training, compute:

- exact normalized prompt hashes
- exact prompt/expected pair hashes
- duplicate IDs
- duplicate source_record_id where available
- template-family distribution
- semantic-signature distribution

At minimum, normalized exact prompt overlap must be zero across:

TRAIN vs DEV
TRAIN vs BLIND
DEV vs BLIND
TRAIN vs S0.5
TRAIN vs S0.7

Normalization used for overlap detection must be frozen in code and recorded
in the manifest.

## 13. Semantic Signatures

Where practical, records should receive a semantic_signature describing the
underlying operation independently of exact wording.

Examples:

identity.query.self
creator.query.source
relation.subject_object
relation.reverse_subject_object
polarity.false_premise
polarity.explicit_negation
entailment.supported
entailment.contradicted
entailment.unknown
coreference.resolve_subject
extraction.literal
generation.constraint_language

The purpose is diagnostic grouping, not exposing hidden reasoning traces.

## 14. DEV Design

DEV target size:

minimum 1,000 examples

Preferred:
1,600 to 2,400 examples

DEV must cover:

- both languages
- all 10 capability families
- all relevant difficulty levels
- hard negatives
- semantic signatures absent as exact prompts from TRAIN

Checkpoint selection must not depend only on global DEV score.

Report per-family and per-language performance.

## 15. Fresh S1 BLIND Design

BLIND target size:

800 examples

Language balance:

English 400
Russian 400

The blind set must be frozen before S1 training.

It must cover all S1 capability families.

Identity replay must be a minority of the blind set.

The blind set must emphasize semantic variation rather than memorized
canonical phrasing.

The dataset SHA256 must be recorded before the first inference.

## 16. S0 Regression Evaluation

S1 does not redefine the historical S0.5 or S0.7 results.

After selecting an S1 candidate using DEV, compare:

S0.4.1 canonical parent
vs
S1 candidate

on the frozen Stage 0 regression assets.

Required reports:

S0.5 Blind-80
S0.7 Fresh Blind-80

These evaluations are regression diagnostics.

They are not training data.

## 17. Scoring

Exact-match scoring is appropriate only where the task has a canonical
deterministic target.

Other task families require deterministic task-specific scoring defined
before blind inference.

Possible deterministic metrics include:

- normalized exact match
- classification accuracy
- token-level F1 for extraction
- constraint satisfaction
- language correctness
- termination correctness

Do not use an unconstrained LLM judge as the sole S1 promotion metric.

## 18. S1.0 Promotion Gate

The final numeric gate for the 800-example S1 BLIND will be frozen after the
blind composition and deterministic scorers are implemented.

However, the following invariants are fixed now:

- candidate must improve overall semantic performance over S0.4.1
- improvement must not be isolated to one language
- no major capability family may catastrophically regress
- EOT / termination behavior must remain stable
- S0 identity behavior must not catastrophically regress
- NULLXES / SHINRA distinction must remain intact
- promotion requires fresh BLIND evidence

DEV performance alone cannot promote a checkpoint.

## 19. Training Manifest Requirement

Before the first optimizer step, create a frozen manifest containing:

- parent checkpoint
- parent weight identity/hash where available
- tokenizer identity
- TRAIN dataset SHA256
- DEV dataset SHA256
- BLIND dataset SHA256
- row counts
- token counts
- language mixture
- capability mixture
- difficulty mixture
- source mixture
- duplicate/leakage audit
- S0 overlap audit
- optimizer configuration
- learning-rate schedule
- batch configuration
- sequence length
- random seeds
- code revision

Training must not begin if the manifest audit fails.

## 20. Stop Conditions

Stop the S1.0 run if:

- loss becomes non-finite
- gradients become non-finite
- repeated severe identity regression appears on DEV diagnostics
- one language collapses while aggregate score rises
- data leakage is discovered
- dataset integrity hash changes unexpectedly

Do not repair a failed blind result by training directly on the failed blind
examples.
