# Explicit audit-only GPU diagnostic

`python -m training.pretrain --diagnostic-audit` is a separate admission path for one explicitly requested run on a pinned `audit_only` corpus. It does not change `training.enabled`, `data.training_enabled`, `runtime.colab_launch_allowed`, source review status, or corpus admission. Without the flag, the trainer continues to require all production gates.

Diagnostic mode requires the exact corpus SHA in `configs/shinra.yaml`, verifies the Native bundle manifest and every bundle-file checksum, and requires train and validation packed manifests to name that same tokenizer bundle. It opens only train and validation. It never opens the blind packed directory. The selected run budget must be `diagnostic`, is capped by the configured 20,000,000-token diagnostic budget, and the first-run step cap defaults to one optimizer update. The scheduler horizon derives from the fixed diagnostic token budget, not the step cap; a resumed run can raise `--diagnostic-max-steps` without changing scheduler state or data/tokenizer identity.

Each checkpoint records `admission: diagnostic_audit` in `training_admission.json`, model config, training state, and metrics. Resume requires the same admission, config, data, tokenizer, and token budget. The scheduler horizon stays fixed; an explicit larger `--diagnostic-max-steps` can continue the run. Inference and Hub publication reject diagnostic checkpoints. Diagnostic checkpoints are not production models and must not be promoted by changing the marker manually.

## GPU memory estimate

For the configured 36-layer architecture, the current preflight estimates about 3.80 billion parameters. It reserves 16 bytes per parameter for weights, gradients, FP32 Adam moments and an update temporary, plus a gradient-checkpoint activation estimate, FP32 vocabulary-loss workspace and 4 GiB runtime workspace. With microbatch 1 and 4096-token rows, that estimate is about 69.9 GB before 10% allocator headroom, or about 77.6 GB of free memory required. This is a conservative analytical estimate, not a measured peak. It does not establish that an arbitrary Colab allocation has that much free VRAM; runtime preflight refuses to allocate the model if reported free memory is lower. No OOM is caught and disguised as a smaller model or fallback mode.

NVIDIA lists 96 GB GDDR7 for RTX PRO 6000 Blackwell editions. That gives nominal capacity above this estimate, subject to runtime reservation and actual free memory. An 80 GB A100 may have little practical margin after runtime reservation and can fail the free-memory preflight; 40 GB is below this estimate. No throughput or run-time estimate is available before a real run. The model configuration retains its existing 32,768 maximum positional context; this run consumes packed 4,096-token rows and does not alter architecture or tokenizer bundle contracts.

## Resume

The trainer publishes each full checkpoint into a temporary sibling directory, hashes all checkpoint files, then renames it to `step-XXXXXXXX`. Save cadence is one optimizer step in diagnostic mode. To resume after Colab disconnect, rerun the same command and set `--resume-from` to the last complete `step-XXXXXXXX` directory. An incomplete temporary directory is never treated as a checkpoint. Keep the output directory on persistent Drive storage with enough free capacity for model weights and optimizer state; Drive rename and sustained write performance must be confirmed in the actual Colab session.

An incomplete one-step run reports `budget_incomplete` because it has not consumed the 20M target. This status means the deliberately capped diagnostic run stopped before its token budget; it does not mean the optimizer update failed. Runtime training success is accepted only after inspecting the actual Colab result and checkpoint.
